# CS230
##Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?
The Gaming Room was a client interested in developing a web-based application for their mobile game, Draw It or Lose It. They wanted us to help with the development of the server environment the game would run on. They also wanted help with developing the game using an object-oriented programming language like Java to create single instances of the game with the Singleton design pattern. 
##What did you do particularly well in developing this documentation?
Within this documentation, I believe my UML diagram and recommendations section are the strongest. The UML diagram helped me understand what the client wanted on a code level, and the recommendations section allowed me to tie everything together and see how all components and decisions need to work as one.
##What about the process of working through a design document did you find helpful when developing the code?
When developing the code, the constraints and requirements sections I outlined in the document helped to make sure I was following what the client wanted for the application. The document allowed me to keep all requirements and constraints in one central location for more efficient callbacks. It also allowed me to think about my development with a broader lens by considering not just making sure the code works on my machine, but on other platforms as well. 
##If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
I would revise my comparison of the different server options. I have never heard of using a mobile device as a server, so that threw me off and I got confused at some points. To improve it, I would look more into using a mobile device as a server, potentially trying to implement one myself, so I can fully understand what is needed to compare and contrast against Mac, Windows, and Linux.
##How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?
When interpreting the user's needs and implement them into my software design, I tried to make sure to break down their request into smaller sections and think about the implications of what they are asking. When they ask for a web-based server application, this immediately tells me that I need to consider an API based on the programming language to use HTTPS, like springboot or RESTful, and front-end/back-end development. It is important to consider the client's needs when designing because it will cause less frustration between client and developer if you start designing with their needs in mind. 
##How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?
When designing software, my number one approach was to make sure all of my client's needs were met efficiently before considering other things they might need. In the future, I would probably take this same approach again.
